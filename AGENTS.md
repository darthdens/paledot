# Project rules

- Stack is TanStack Start (SSR) with file routes in `src/routes/`; react-router-style imports go through `src/lib/router-compat.tsx`. Why: SSR lets each domain serve its own link-preview tags.
- One app serves two brands; `src/lib/site-brand.ts` picks the brand from the request host (`?site=` overrides for previews), and `src/lib/site-meta.ts` holds per-brand head tags. Why: both domains must share every update but stay separately branded.
- The 3D explorer and page components load client-only (lazy, after mount) from `src/routes/index.tsx`. Why: three.js/WebGL can't run during server rendering.
- The Echo AI widget script is injected after hydration in `__root.tsx`, never as a head/body tag. Why: it adds DOM nodes to <body> that break React hydration.
- Left Behind data is fetched from the JPL Horizons API and NASA Image and Video Library API during the event and saved as static files in `public/left-behind/`; feature code stays in `src/features/left-behind/` and reads only through its cached data client, with no Cloud storage, functions or auth. Why: keep the layer isolated, reproducible and available without a data service.
- Left Behind stores only menu and machine UI state; Pale Dot mounts its layer after boot when machinesVisible, and title/hash requests open the menu after boot. Why: machines belong to the same universe, not an alternate mode.

- Solid-body renderers and close-up navigation use the shared bodyScale helpers; catalogue sizes remain diameters and positions are untouched. Why: both brands/modes must agree on radius, camera clearance and portrait framing.
- In development only, window.__cosmosCheck exposes live state(), snapshot(), finishFlight(), zoomTo() and the leftBehind store (use it, not dynamic imports, which load separate store copies); the canvas marks data-scene-ready after drawing. Why: verify complete tours and true radii without duplicating stores or waiting for software-GPU animation time.
- Both brands share useSimClock and ephemerides; the opening readout and pre-motion frames share one elapsed-time cursor, respecting tour pauses. Begin at Earth restores playback. Why: time ticks before loading without doubling in the scene.

- Welcome and Left Behind menus share TourChoices; only implemented tours are launchable. Why: every entry offers the same options without substituting another tour for unfinished machine tours.

- Pale Dot renders one persistent second-precision simulation-date readout above every page state, with reserved explorer space; DateControl remains on the existing Clock control. Why: the simulation date must stay visible without hover or overlapping controls.
- Machine tracks load static data after boot, evaluate positions in heliocentric ecliptic kilometres, and use the single frame helper; markers publish hw-prefixed world positions for the existing camera. Why: paths, measurements and navigation must share the planets' frame without changing ordinary exploration.
- NASA GLB models render at at true size from hardware.json trueSize (the HTML ring is the only screen-size marker); following hardware ties camera near to target distance and lowers minDistance/body clearance so users can zoom to metre scale. Why: hardware stays findable from afar yet true-scale up close, and CPU-side double-precision matrices keep metre detail stable at heliocentric distances.
- Pale Dot menus use the explorer's reserved-date-strip coordinate space; trail buffers store parent-local points from index zero. Why: fixed viewport offsets and unfilled/world-space buffer prefixes produce displaced menus and lines.
- Pale Dot Quick Jump categories share JumpCategory and selected-body/machine panels share ObjectPanelHeader. Why: one category expansion state and shared controls prevent NASA UI from drifting from the explorer.
- Moon/Mars pins render through SurfaceSlot (inside each body's spinning mesh) from the useSurfaceAttachments registry, positioned with lib/geo latLonToLocal and per-body texture offsets; landed pins publish world positions in pinRegistry for tracks, descent arcs and the camera. Why: pins must turn with the texture, and only the Pale Dot machines layer may register them.

- Earth/Moon/Mars HD global maps (public/textures/hd) download behind the opening loader and are applied/GPU-uploaded at once via hdSurfaces.ts; landing-site NASA imagery (public/left-behind/terrain, built by scripts/left-behind/fetch_surfaces.py) renders as SitePatch caps that modulate the global colour. Why: boot stays fast and real detail blends with the body.
- App images and textures are WebP (only favicons, app icons and og/social preview images stay PNG); keep each file under 10 MB. Why: faster loading, and some platforms require PNG icons/previews.
- Earth/Moon/Mars/Mercury/Ceres real relief: global height maps (src/assets/relief, CDN assets) are fetched and decoded behind the opening loader (Skip continues in background) and displace a denser body sphere with per-fragment normals via lib/relief.ts once near; landing sites add DTM heights to near SitePatch caps, the body discards fragments under the mid cap (holeRect), and pins/camera/scale use pin.centre + pin.groundAt. Why: true-scale terrain with millimetre-stable caps and no coarse sphere poking through.
- Planet, cloud and SitePatch shaders light colour textures in linear space and end with `#include <colorspace_fragment>`; cloud maps are NoColorSpace coverage data; clouds sit ~10 km up, turn with the body and drift on the simulation clock. Why: unencoded linear output made sunlit surfaces too dark, and wall-clock cloud motion looked fake; any future detailed body must follow the same rules.
- Tours live in a registry (`src/components/cosmos/data/tours.ts`); Pale Dot registers Left Behind tours, stops with date/follow drive the shared clock and the normal machine follow, and only onEnd "end-frame" tours dispatch cosmos:journey-end. Why: one tour engine and card for every tour without changing Begin at Earth.
- Machine tour stops fly between anchored views (body/machine/pin + offset) on a van Wijk zoom-and-pan path computed from same-date positions, frame landed hardware in its ground-normal basis, and show temporary trails only for the current stop's machine. Why: per-frame stale world positions caused jumps, and constant perceived speed avoids rush/flicker.
- Narrative machine-tour viewpoints use tourView with dated world positions for encounter pairs and Sunward look-backs; archival photos resolve through the cached manifest with captionText. Why: the view must match narration without claiming measured spacecraft attitude or mistaking archival imagery for simulation output.
- Tour autoplay uses a slide-keyed elapsed timer with current callbacks and pause state; duration derives from that slide's dates. Why: scene rerenders must not restart countdowns, and resume must retain elapsed narration time.
- Voyager 1's One last look is a nested sequence in its existing tour; its frame override holds camera position while rotating and uses cached matching-date Horizons data for measurements. Why: preserve physical scale, clock pause, direct hash entry and heliopause continuation without repeated follow flights.
- One last look supplies content and nested navigation to the same TourOverlay panel renderer as ordinary stops. Why: card sizing, controls, collapse, swipes and progress cannot drift into a separate tour interface.
- Signal races snapshot real-UTC Earth-relative distances at send time, persist locally, and use the shared frame conversion for their pulse; never drive the simulation clock. Why: reopening preserves elapsed light time independently of exploration.
- Left Behind framing uses a boot-gated UI overlay state, shared date-safe machine navigation, and a Voyager-1-only summary; Credits are imported from the repository Markdown. Why: entry disclosures stay separate from ordinary menu use, with no new scene or data service.
- Left Behind entry, summary and other modals share DialogSurface and the tour-photo overlay. Why: match Send a signal without special summary styling.
